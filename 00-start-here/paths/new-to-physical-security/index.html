New to physical security

Start with the main systems, then work through the networking, identity and event handling needed for an integration.

Sources and scopeRead before use

Navigation or project guidance; not a claim of product, standards or environment validation.

Verification and testing

On this page
  • 1. Draw the system
  • 2. Get the meanings straight
  • 3. Find the boundaries
  • 4. Make room for failure
  • Where to go next

1. Draw the system#

Read system architecture, then architecture and layering. Draw the controller, network, adapter, application and operator. Mark the control path separately from the observation path.

You should be able to explain: which component observed the condition, which component made a decision, and which component only displayed information.

2. Get the meanings straight#

Read events, state, commands and time and data models. Keep the raw event, device time, receipt time and mapped event together.

Check yourself: receiving a forced door event does not establish that the door is still open now.

3. Find the boundaries#

Read identity and permissions and trust boundaries. Decide what the adapter needs to read and what it must not be allowed to change.

4. Make room for failure#

Read failure semantics. Describe what the application shows when the controller is unreachable, its clock is wrong or a message arrives twice.

Where to go next#

Pick access control, video or events. Keep the glossary nearby. You do not need to memorise every acronym before making progress.
